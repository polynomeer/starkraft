# 삼재 디자인 적용 작업계획서

## 목적

[디자인 시안](https://claude.ai/artifact/53Te38p8czaacWt5EKnbBu)을 실제 게임에 적용하기 위한 순서, 범위, 완료 기준을 정한다.

시안은 "조선펑크 설화 RTS"로, 천(天)·지(地)·인(人) 세 종족을 다룬다. 지금 게임은 유닛 3종과 건물 3종을 도형으로 그리는 샌드박스다. 그래서 이 작업은 그림 교체가 아니라 렌더링, UI, 게임 데이터, 규칙을 모두 바꾸는 일이다.

## 현재 게임과 시안의 차이

아래 "현재"는 코드에서 확인한 내용이다.

| 영역 | 현재 | 시안 | 규모 |
| --- | --- | --- | --- |
| 월드 렌더 | `ShapeRenderer` 도형만 사용, `SpriteBatch` 그림 경로는 `5149344`에서 제거 | 음영이 깊은 2.5D 그림 | 중 |
| 화면 투영 | 정사각 격자 탑다운, 타일 20px, 줌 잠금 | 2:1 아이소메트릭 | 대 (좌표 변환 호출 151곳) |
| 로스터 | 유닛 `Worker`·`Marine`·`Zergling`, 건물 `Depot`·`ResourceDepot`·`GasDepot` | 유닛 20종, 건물 21종, 영웅 9명 | 대 |
| 종족 | 개념 없음, `faction`은 진영 번호뿐 | 세 종족이 몸, 건설 방식, 죽는 방식에서 다름 | 대 |
| 자원 | `minerals`, `gas` | 귀화석, 산기, 식량 | 소 (식량은 신규) |
| 보급 | sim에 없음 | 식량 상한과 보급 건물 | 중 |
| 공중 유닛 | sim에 없음 | 비거, 어둑시니, 솟대 오리 | 중 |
| 능력 | 공격과 채집뿐 (치유, 오라, 영역, 시체 없음) | 종족별 고유 규칙, 영웅 스킬 | 대 |
| 글꼴 | libGDX 기본 `BitmapFont`, 한글 글리프 없음 | 나눔명조, IBM Plex Sans KR, IBM Plex Mono | 중 (의존성 추가) |
| 화면 | 메인 메뉴, 게임 | 메인, 로비, 결과, 인게임 HUD | 대 |
| 효과음 | 시작할 때 합성한 신호음 | 별도 시안 없음 | 범위 밖, 7단계에서 검토 |
| 서버 | Go 서버가 자체 최소 유닛 모델 사용, Kotlin sim을 호출하지 않음 | 해당 없음 | 별도 결정 (아래 참조) |

## 원칙

- **결정론을 지킨다.** 시스템 순서와 순회 순서는 월드/리플레이 해시의 일부다. sim을 바꾸는 단계는 해시 변경을 의도한 변경으로 명시하고 `DeterminismTest`와 스크립트를 함께 갱신한다.
- **그림은 클라이언트에 둔다.** 게임 규칙은 `sim` 코어에, 렌더링과 UI 상태는 `client`에 둔다.
- **언제든 돌아갈 수 있게 한다.** 그림이 없는 타입은 기존 도형으로 그린다. 단계마다 게임이 실행되는 상태로 끝낸다.
- **성능을 재며 간다.** 이전 스프라이트 경로는 성능 문제로 제거되었다(`5149344`). 현재 PNG는 1장에 약 2MB이고, 불러올 때 픽셀을 전부 훑는다. 같은 문제를 반복하지 않도록 크기 예산을 둔다.
- **독창성을 지킨다.** 시안의 원칙대로 다른 게임의 모습을 따르지 않는다. 무속은 품위 있게 묘사한다(`art/sampajeon/design2/SPEC_TJI.md`).
- **검증한 내용만 출처로 적는다.** 설화와 인물의 출처 문구는 SPEC에 적힌 범위를 넘지 않는다.

## 주요 결정

| 번호 | 결정 | 이유 | 상태 |
| --- | --- | --- | --- |
| D1 | 시안 원본 생성기와 SPEC을 `art/sampajeon/`에 보관한다 | 지금까지 임시 폴더에만 있어 사라질 수 있었다 | 적용 |
| D2 | SVG 생성기에서 PNG를 뽑아 리소스에 넣는다. 게임에서 SVG를 직접 그리지 않는다 | 필터가 많은 SVG는 실시간으로 그릴 수 없고 libGDX도 지원하지 않는다 | 적용 |
| D3 | sim 격자는 그대로 두고 아이소메트릭은 클라이언트 투영으로만 처리한다 | sim, 리플레이, 서버, 맵 포맷에 영향이 없다 | 권장 |
| D4 | 타입 ID는 영문으로 새로 정한다 (예: `JoseonArtisan`). 한글 이름은 표시용 데이터로 분리한다 | ID는 스크립트와 리플레이에 쓰인다. `Marine`, `Zergling`은 시안과 맞지 않는다 | 권장 |
| D5 | 일꾼과 부대가 쓰는 공통 규칙을 먼저 만들고 종족 규칙은 그 위에 올린다 | 같은 메커닉을 종족마다 따로 만들지 않기 위해서다 | 권장 |
| D6 | 로컬 플레이(`:sim:play`)를 먼저 완성한다. Go 서버의 로스터는 8단계에서 다룬다 | 서버가 sim을 호출하지 않아 규칙을 이중으로 구현해야 한다 | 권장, 확인 필요 |

## 기존 문제

코드를 조사하며 찾은 문제로, 이번 작업이 만든 것은 아니다.

- **`:sim:test` 19건 실패 (해결):** 대부분 이전 변경을 따라가지 못한 테스트였다. 해시 기준값 3건은 `1975398`(유닛 속도 상향) 이후 갱신되지 않았다. 이분 탐색으로 이 커밋이 원인임을 확인했고, 그 커밋과 현재의 해시가 같음을 확인한 뒤 갱신했다. `MovementSystem`이 데이터에 없는 유닛 타입에서 예외를 던지던 버그는 코드를 고쳤다.

- **자원 종류 불일치:** 클라이언트 스냅샷의 `kind`는 `MineralField`·`GasGeyser`인데 렌더러는 `"gas"`와 비교한다. 그래서 도형 렌더에서는 가스도 광물처럼 그려졌고, 테스트는 현재 값을 고정하고 있다. 스프라이트는 양쪽 이름을 모두 등록해 우회했으며 4단계에서 정리한다.

## 단계별 작업

크기는 소·중·대의 상대 규모다. 각 단계는 이전 단계가 끝나야 시작한다. 단, 3단계(UI)는 2단계와 나란히 진행할 수 있다.

### 0단계: 시안 보존과 계획 (소)

- [x] 생성기와 SPEC을 `art/sampajeon/`으로 옮기기
- [x] 이 계획서 작성, `docs/README.md`에 등록

**완료 기준:** 저장소만으로 시안을 다시 생성할 수 있다.

### 1단계: 스프라이트 파이프라인과 월드 첫 적용 (중)

sim을 건드리지 않고 지금 있는 타입에 시안의 그림을 입힌다. 파이프라인과 성능을 일찍 검증하는 것이 목적이다.

- [x] `art/sampajeon/export_sprites.py`: 생성기에서 배경 없는 그림을 뽑아 헤드리스 Chrome으로 PNG 생성
- [x] `visuals.json` 확장: 기준점(`anchorX/Y`)과 표시 크기(`widthTiles`)
- [x] `GdxSpriteAssets`: 기준점이 있으면 여백 자르기 생략, 밉맵 적용
- [x] `GdxWorldRenderer`: 도형 패스와 분리된 스프라이트 패스, y 정렬, 그림이 없으면 기존 도형 사용
- [x] 임시 대응: `Worker`→공방 일꾼, `Marine`→화승총수, `Zergling`→방망이 장사, `Depot`→관상감 본청, `ResourceDepot`→곳간, `GasDepot`→산기 증류소, `minerals`→귀화석, `gas`→산기
- [x] 실제 창에서 화면 확인: `STARKRAFT_CAPTURE_PATH`로 한 프레임을 PNG로 저장해 확인 (안개에 가려진 `Zergling`, 곳간, 증류소는 아직 게임 화면에서 보지 못함)
- [x] 이전 샘플 PNG 제거 (약 11MB)
- [x] 발견한 버그 수정: 건물 그림과 선택 표시가 실제 점유 타일에서 한 칸 어긋남, 월드 도형의 반투명이 적용되지 않음

**완료 기준:** `:sim:play`에서 전 유닛과 건물이 시안의 그림으로 보이고, 선택·체력바·피격 효과가 유지되며, `./gradlew :sim:build`와 결정론 테스트가 통과한다.

**한계:** 시안의 그림은 유닛당 한 포즈다. 이 단계에서는 좌우 반전과 기존의 흔들림 연출만 쓴다. 걷기 프레임은 7단계에서 다룬다.

### 2단계: 아이소메트릭 화면과 지형 (대)

- [ ] `CameraView`에 x와 y를 함께 받는 투영 함수 도입, 호출 151곳 이전 (`GdxWorldRenderer` 83, `ClientRenderer` 32, `GdxClientRuntime` 16, `GraphicalClient` 16, `ClientUiCompat` 4)
- [ ] 역투영: 클릭 선택, 드래그 박스, 건물 배치, 카메라 이동 경계 (테스트 포함)
- [ ] 보이는 타일 계산을 마름모 영역에 맞게 변경
- [ ] 기본 타일 크기 조정: 3×3 건물을 시안의 비례로 보이게 하려면 현재 20px로는 부족하다. 줌 잠금 해제도 함께 검토
- [ ] 지형 타일 추출 (`terrain.py`): 풀, 논, 강, 돌담, 소나무, 전환 타일
- [ ] 미니맵을 시안대로 지도 그림 스타일로 변경

**완료 기준:** 건물 바닥이 격자와 맞고, 어떤 줌에서도 클릭한 타일이 정확히 선택되며, 60 FPS를 유지한다. 기준은 유닛 100개 + 건물 20개로 측정한다.

### 3단계: UI와 글꼴 (대)

- [ ] `gdx-freetype` 의존성과 OFL 글꼴 3종 추가, 라이선스 파일 포함, 한글 글리프 생성
- [ ] 색 토큰을 시안 값으로 교체, 남은 `Color` 리터럴 정리 (`docs/presentation-theme-spec.md` 갱신)
- [ ] 인게임 HUD: 옻칠 나무 틀, 단청 띠, 초상 + 상태 카드, 부대 슬롯, 명령 그리드, 알림 카드 (`docs/hud-layout-contract.md` 준수)
- [ ] 메인 메뉴 시안 적용
- [ ] 로비(종족 선택 포함)와 결과 화면 신규 구현
- [ ] 표시 이름 한글화, 메인 메뉴 제목을 `SAMJAE`에서 한글 `삼재`로 변경 (창 제목은 이미 `삼재 SAMJAE`)

**완료 기준:** 모든 화면의 글자가 한글로 깨지지 않고, `COMMAND_CONTRACT.md`의 입력 규칙이 그대로 동작한다.

### 4단계: 데이터 재편 (대)

게임 규칙은 아직 그대로 둔 채 이름과 구조만 바꾼다. 해시가 바뀌는 첫 단계다.

- [ ] 타입 ID 변경과 `Gauss`·`Claw` 등 무기 ID 변경 (테스트 27개 이상, `sim/scripts/*`, `ClientCatalog`, `ClientUiCompat`, 벤치마크, `tools`)
- [ ] 코드에서 `typeId.contains("Marine")`식 분기를 `archetype`이나 데이터 필드로 교체
- [ ] `UnitDef`, `BuildingDef`에 종족 필드 추가, `tools/schema/data-defs-v1.schema.json` 갱신
- [ ] 식량(보급) 규칙 추가: 상한, 생산 거부 사유, HUD 표시
- [ ] 시안 수치를 `docs/balance-spec.md`에 초안으로 정리: 비용, 체력, 무기

**완료 기준:** `:sim:build`, `:tools:smoke`, `scripts/e2e_server_bots_smoke.sh`가 통과하고 리플레이 해시 변경 사유가 `docs/replay-format-spec.md`에 적혀 있다.

### 5단계: 종족 규칙 (대)

종족당 유닛 6~7종, 건물 7종을 구현한다. 공통 규칙부터 만든다.

| 공통 규칙 | 쓰는 곳 |
| --- | --- |
| 공중 유닛 (경로, 충돌, 공격 대상) | 비거, 어둑시니, 솟대 오리 |
| 치유와 약화 | 무당, 바리공주 |
| 오라 | 오방신장 |
| 시야 가림 | 어둑시니 |

| 종족 | 고유 규칙 | 주요 작업 |
| --- | --- | --- |
| 인 조선 공방 | 잔해가 남아 일꾼이 되살림, 거치 사격 | 잔해 엔티티, 수리 명령, 일제 사격 |
| 지 요물 무리 | 싸울수록 강해짐, 쇠를 먹어 성장, 쓰러진 적을 잠시 아군으로 | 성장 상태, 임시 소속 변경 |
| 천 오방 신당 | 금줄로 성역 확장, 성역 안에서 강함, 혼이 잠시 머묾 | 영역 맵, 영역 보너스, 사후 지연 |

- [ ] 생산 트리와 건물별 해금
- [ ] 새 상태는 모두 `World` 순회 순서가 고정되게 저장, 스냅샷 NDJSON 레코드 추가
- [ ] 봇이 세 종족을 플레이할 수 있게 갱신 (`docs/ai-behavior-spec.md`)
- [ ] 규칙마다 결정론 단위 테스트

**완료 기준:** 세 종족의 조합 9가지가 자동 대전으로 끝까지 진행되고 같은 시드에서 해시가 같다.

### 6단계: 영웅 (중)

| 스프라이트 전체 | 40MB 이하 (2단계 후 재평가) |
| 프레임 시간 | 기준 장면에서 16.6ms 이하 |

런타임 아틀라스가 필요해지면 libGDX 코어의 `PixmapPacker`를 쓴다. 추가 의존성이 필요 없다.

## 위험

| 위험 | 영향 | 대응 |
| --- | --- | --- |
| 스프라이트 성능 저하 재발 | 플레이 불가 | 1단계부터 크기 예산 적용, `scripts/play_sim_profile.sh`로 측정 |
| 그림이 작은 크기에서 뭉개짐 | 유닛 구분 불가 | 시안은 큰 그림 기준이므로 실제 표시 크기에서 확인, 필요 시 윤곽 강화 |
| 아군과 적이 같은 그림일 때 구분 불가 | 조작 실수 | 발밑 진영 고리 유지, 동족전 색 구분 설계 |
| `GdxWorldRenderer` 등 대형 파일 충돌 | 회귀 | 투영 변경은 별도 커밋, 기능 추가와 섞지 않음 |
| 생성기 재실행 시 파일 크기 초과 | 캔버스에서 보드 사라짐 | `gen2/README_build.md`의 크기 줄이기 절차 준수 (2MiB 제한) |
| 시안에 없는 수치와 규칙 | 밸런스 붕괴 | 4단계에서 초안 작성, 자동 대전 통계로 조정 |
| 글꼴 라이선스 | 배포 문제 | OFL 글꼴만 사용, 라이선스 동봉 |

## 제품 이름

제품 이름은 **삼재(三才/三災), 영문 SAMJAE**로 정했다. 천·지·인을 뜻하는 三才와 재앙을 뜻하는 三災의 소리가 같다. 시안 초기 이름은 삼파전이었다.

- 저장소, `starkraft.*` 패키지, `STARKRAFT_*` 환경 변수는 코드 이름으로 두고, 공개 전에 따로 바꾼다.
- 시안 안의 이름과 로고는 삼재로 바꿨다. `art/sampajeon/` 등 경로에는 옛 이름이 남아 있다.
- 상표는 아직 조회하지 않았다. 출시 전에 특허청 조회가 필요하다.

## 확인이 필요한 사항

1. **네트워크 대전 범위(D6):** 8단계를 이번 범위에 넣을지.
2. **글꼴 파일:** 3단계 시작 전에 Google Fonts의 OFL 글꼴을 내려받아 저장소에 넣어도 되는지.
3. **애니메이션 수준:** 유닛당 걷기와 공격 프레임을 어느 정도까지 만들지. 프레임 수만큼 용량이 늘어난다.
