# Product Vision

## 목적

`starkraft`의 제품 방향을 한 문서로 고정한다.  
이 문서는 기능 우선순위, UI 투자, 네트워크 구조, 릴리스 판단의 기준이 된다.

## 제품 한 줄 정의

`starkraft`는 결정론적 시뮬레이션과 재현 가능한 리플레이를 기반으로 한 1v1 실시간 전략 게임 스택이다.

## 타깃 사용자

### 1차 사용자

- RTS 메커닉을 빠르게 검증하려는 개발자
- deterministic sim / authoritative server 구조를 실험하려는 엔지니어
- headless replay / benchmark 기반으로 밸런스를 조정하려는 디자이너

### 2차 사용자

- 로컬 또는 제한적 온라인 환경에서 1v1 매치를 플레이하려는 플레이어
- 리플레이 분석과 관전을 중요하게 보는 숙련 플레이어

## 핵심 가치

### 결정론

- 같은 입력이면 같은 결과가 나온다.
- 디버깅, 밸런스 조정, 리플레이 검증 비용이 크게 줄어든다.

### 권위 서버

- 클라이언트는 입력/표시 계층이다.
- 판정과 상태 변경은 서버 또는 `sim`의 규칙을 따른다.

### 관측 가능성

- replay, hash, snapshot, ack reason을 통해 상태를 추적할 수 있다.

### 확장성

- `sim`, `server`, `client`, `tools`, `shared-protocol` 분리로 기능 확장이 가능하다.

## 제품 목표

### 단기 목표

- 한 사용자가 로컬에서 전체 스택을 실행할 수 있을 것
- 1v1 경기의 시작부터 종료까지 반복 재현 가능할 것
- replay와 golden hash로 회귀를 잡을 수 있을 것

### 중기 목표

- 그래픽 클라이언트가 디버그 뷰어를 넘어서 플레이 가능한 UX를 제공할 것
- 서버 기반 멀티플레이 흐름이 안정적으로 동작할 것
- 자원/생산/연구/전투의 기본 메타가 성립할 것

### 장기 목표

- 제품 수준의 UI/HUD/입력 체계
- 장시간 세션 안정성
- 패키징/릴리스 자동화

## 비목표

현재 범위 밖:

- 대규모 캠페인 콘텐츠
- 상용 아트/오디오 파이프라인 완성
- MMO 규모의 서버 기능
- 모바일 플랫폼 지원

## 제품 품질 기준

제품 수준으로 보려면 최소한 다음이 필요하다.

1. 로컬 및 서버 기반 1v1 플레이 가능
2. 매치 종료와 결과 기록이 안정적
3. replay가 검증 가능
4. 클라이언트 입력과 HUD가 실사용 가능
5. soak/perf 기준을 통과

## 성공 지표

- 15분 이상 경기에서 클라이언트 사용성 병목이 크지 않을 것
- 동일 replay 재실행 hash 불일치가 없을 것
- smoke/CI 경로가 안정적으로 green일 것
- command rejection reason이 운영 가능한 수준으로 관측될 것

## 현재 제품 리스크

- 그래픽 클라이언트 UX가 아직 제품 수준이 아님
- 네트워크 멀티플레이 운영 경험이 충분히 축적되지 않음
- 밸런스 문서와 실제 데이터의 장기 동기화 체계가 약함
